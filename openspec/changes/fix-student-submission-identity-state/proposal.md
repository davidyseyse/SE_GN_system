## Why

學生成功提交答案後，提交事件會觸發答案重新載入，但學生端以外部登入 ID 比對後端回傳的內部使用者 UUID，導致無法辨識自己的 submission。重新載入因此清除本回合的已提交狀態，使「取消鎖定」按鈕再次出現，與後端禁止已提交者取消的規則不一致。

## What Changes

- 在已提交答案的讀取模型中提供不含歧義的「是否為目前請求者」資訊，避免前端跨 ID 命名空間比對。
- 學生端以伺服器提供的本人 submission 判定恢復題目與回合層級的已提交狀態。
- 合併非同步重新載入結果時保留剛完成的本地提交狀態，避免較舊請求覆蓋成功結果。
- 確保提交成功後、即時事件刷新後及重新連線後，「取消鎖定」皆維持隱藏。
- 加入 API 契約、學生狀態與重新載入競態的回歸測試。

## Capabilities

### New Capabilities

- `student-submission-state-recovery`: 定義學生端以權威且無歧義的身分資訊恢復目前回合已提交狀態，並在提交後禁止顯示取消鎖定操作。

### Modified Capabilities

無。

## Impact

- API：目前回合答案清單的學生可見讀取模型。
- Web：`SubmittedAnswerView` 契約、學生端答案重新載入、已提交狀態合併與取消鎖定顯示條件。
- 測試：submission API 回應、提交後即時刷新、重新連線與非同步回應順序。
- 不變更資料庫 schema、既有 submission 資料或取消鎖定的後端授權規則。
